# StarBlog Client 主界面重新设计方案

## 1. 目标

重新设计 StarBlog Client（原 StarBlog Publisher）的「发布 / Markdown 编辑」主界面。

本次目标不是简单替换控件或调整样式，而是重新设计整个工作区的信息架构和交互层级。

技术栈继续采用：

- Avalonia
- FluentAvalonia
- C#
- MVVM

视觉参考：

- Starward
- VS Code
- Typora
- Obsidian
- Windows 11 / WinUI Fluent Design

不要照搬具体 UI，但参考这些软件的：

- 内容优先
- 克制的 Fluent 风格
- Compact Navigation
- Inspector
- CommandBar / Flyout
- 清晰的信息层级

---

# 2. 核心设计原则

StarBlog Client 是一个**内容生产工具**。

因此：

> Markdown 文档必须是整个界面的绝对视觉中心。

不要继续沿用旧版：

- 大量 Card
- 大量永久可见按钮
- 所有功能平铺
- Markdown 编辑器只是众多控件中的一个

新的界面应该更像：

> VS Code / Typora / Obsidian + Inspector

即：

- 中间：Markdown Editor
- 右侧：文章 Inspector
- 左侧：Compact Navigation
- 顶部：文档操作
- 底部：Status Bar

---

# 3. 整体布局

建议结构：

```text
┌────┬───────────────────────────────────────────────────────────┐
│    │ article.md                                 预览   发布 ▾ │
│    ├────────────────────────────────────┬──────────────────────┤
│    │                                    │                      │
│ 图 │                                    │   文章属性           │
│ 标 │                                    │                      │
│ 导 │         Markdown Editor            │   标题               │
│ 航 │                                    │   描述               │
│    │                                    │   分类 / 标签        │
│    │                                    │   Slug               │
│    │                                    │                      │
│    │                                    │   AI 工具            │
│    │                                    │                      │
│    ├────────────────────────────────────┴──────────────────────┤
│    │ 已保存 · 1423 字 · 3 张图片 · StarBlog ● Connected       │
└────┴───────────────────────────────────────────────────────────┘
````

重点：

* Editor 占据最大空间
* Inspector 是辅助区域
* Navigation 不应该抢占空间
* 发布是 Primary Action

---

# 4. 左侧 Navigation

使用 FluentAvalonia `NavigationView` 的 Compact / LeftCompact 模式。

常态宽度建议：

```text
48 ~ 60 px
```

菜单：

```text
发布
公众号排版
设置
关于
```

默认只显示图标。

鼠标 Hover 使用 Tooltip。

点击汉堡菜单后可以展开显示文字。

不要长期使用现在约 300px 的宽侧边栏。

---

# 5. 顶部 Command Bar

顶部不要再出现巨大标题或功能区域。

建议：

左侧：

```text
article-name.md
```

可以显示：

* 文件名
* 修改状态
* 文件路径 Tooltip

右侧：

```text
预览
发布 ▾
⋯
```

其中：

### 发布

是 Primary Button。

下拉菜单以后可以支持：

```text
发布到 StarBlog
发布并打开网页
复制发布链接
```

### 更多 `⋯`

放置低频操作：

```text
复制 Markdown
生成封面
分析图片
重新加载
```

不要把这些操作全部永久展示在界面底部。

---

# 6. Markdown Editor

Editor 是主界面的核心。

尽量减少外框、Card 和装饰。

建议：

* 占据主工作区约 65%~75%
* 无明显 Card
* 轻量 Border 或直接与 Background 融合
* 支持滚动
* 保持足够大的编辑面积

如果当前没有打开 Markdown：

Editor 区域显示 Empty State：

```text
拖放 Markdown 文件到此处

或

[ 打开文件 ]
```

文件加载之后 Empty State 完全消失。

不要像旧版一样永久保留一个大型「拖放文件」区域。

---

# 7. Inspector

右侧设计为文章 Inspector。

宽度建议：

```text
300 ~ 360 px
```

结构：

```text
文章属性

标题
[............................] ✨

描述
[............................]

分类
[C# ×] [ASP.NET Core ×]    + 添加

关键词
[AI ×] [C# ×]              + 添加

Slug
[............................]

高级设置 ▾
```

Inspector 不要设计成大型 Card。

它应该类似 VS Code / Obsidian 的 Properties Panel。

---

# 8. AI 功能重新整理

目前 UI 中存在：

```text
重置
AI润色
重新生成
生成
生成Slug
生成关键词
```

这些按钮过多，会严重干扰视觉层级。

改成统一的 AI 入口：

```text
✨
```

例如标题输入框：

```text
标题
[................................] ✨
```

点击 `✨` 打开 Flyout：

```text
AI 优化标题
重新生成标题
专业润色
简化标题
恢复原文
```

文章级 AI 功能可以集中放入：

```text
✨ AI
```

菜单：

```text
生成摘要
生成关键词
生成 Slug
生成封面
分析文章图片
```

AI 应该是辅助功能，而不是永久占据大量 UI。

---

# 9. 分类设计

不要永久显示完整 Category Tree。

目前分类树占用了 Inspector 大量空间。

新的设计：

```text
分类

[C# ×]
[ASP.NET Core ×]

+ 添加分类
```

点击：

```text
+ 添加分类
```

打开 Searchable Flyout / Dialog：

```text
搜索分类...

□ AI
□ Android
☑ ASP.NET Core
☑ C#
□ DevOps
□ Docker
```

支持搜索、选择和多选。

---

# 10. Status Bar

底部增加轻量 Status Bar。

例如：

```text
已保存 · 1423 字 · 3 张图片 · UTF-8          StarBlog ● Connected
```

可以显示：

* 保存状态
* 字数
* 图片数量
* 当前后端连接状态
* 当前账号
* AI Provider（可选）

Status Bar 高度约：

```text
24 ~ 30 px
```

不要做成 Card。

---

# 11. Fluent 视觉规范

整体采用 Fluent / WinUI 风格。

要求：

* 少 Card
* 少大圆角
* 少高饱和度颜色
* Accent Color 只用于重要状态和 Primary Action
* 主要层级依靠：

  * spacing
  * typography
  * opacity
  * hierarchy
  * surface
* Light / Dark Theme 都需要正常工作

推荐：

```text
普通 CornerRadius：4~8
大容器尽量无 Border
Navigation 使用 FluentAvalonia 原生样式
Button 尽量保持 WinUI 风格
```

避免：

```text
GlassCard 套 GroupBox
Card 套 Card
所有按钮不同颜色
所有功能永久显示
```

---

# 12. 响应式布局

正常窗口：

```text
Navigation + Editor + Inspector
```

窗口较小时：

Inspector 自动收缩。

进一步缩小时：

Inspector 可以变成：

```text
右侧 Drawer / Flyout
```

Editor 始终优先保证空间。

---

# 13. 暂时不要改的内容

本阶段重点只重新设计：

> Publish Workspace / Markdown Editor 主界面

以下页面暂时保持当前 FluentAvalonia 版本：

* 公众号排版
* 设置
* 关于

因为这些页面当前结构已经基本可用。

不要同时大规模修改所有页面。

---

# 14. 实现要求

优先复用现有：

* ViewModel
* Command
* Service
* Business Logic

主要重构：

```text
View / Layout / Navigation / Interaction
```

不要为了 UI 重写业务逻辑。

允许重新拆分 View：

```text
PublishWorkspaceView
MarkdownEditorView
ArticleInspectorView
CategoryPicker
AiActionFlyout
StatusBar
```

---

# 15. 最终验收标准

完成后主界面应该满足：

1. 第一眼看到的是 Markdown 文档，而不是按钮和 Card
2. Editor 是绝对视觉中心
3. 发布操作明显但不抢占空间
4. Inspector 清晰但安静
5. AI 功能不再散落满屏
6. 分类树不再永久占据大量面积
7. Navigation 默认 Compact
8. 没有大面积无意义 Card
9. 整体更像桌面生产力软件，而不是 Web Admin
10. 视觉气质接近 Starward / VS Code / Obsidian，而不是简单的 Avalonia Demo

本阶段优先完成一个可以运行的主界面版本，然后根据实际截图继续调整视觉细节。



```

我觉得这里面最关键的其实就三句话，最好确保 Grok Build 不要跑偏：

> **不要保持旧布局。**  
> **不要只是把旧控件换成 FluentAvalonia 控件。**  
> **Editor 是产品主角，其他所有 UI 都服务于 Editor。**

尤其“没有打开文件”和“已经打开文件”应该是**两个完全不同的状态**。过去那个巨大的拖拽区一直挂在编辑器上方，是这一版最该首先消灭的东西。
```
