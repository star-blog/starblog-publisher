# 文章工作区

主界面采用常驻文件工具栏、文档标签、文件侧栏和文章属性面板。源码、分栏、预览切换位于编辑区顶部。文件侧栏可折叠，文章属性面板可折叠和拖动调宽。

## 文件操作

- `Ctrl+N`：新建文章。
- `Ctrl+O`：打开一篇或多篇 Markdown；也支持拖放 `.md` / `.markdown` 文件。
- `Ctrl+S`：保存正文与文章属性。新建文章首次保存时选择文件位置。
- `Ctrl+W`：关闭当前文章。未保存时提供保存、不保存、取消。
- `Ctrl+Tab`：切换到下一个标签。
- `Ctrl+B`：展开或收起文件侧栏。

同一路径重复打开会切换到已有标签。标签的圆点表示正文或发布属性有未保存修改。关闭最后一个标签返回欢迎页，打开入口始终可用。退出窗口也会检查每篇文章；有发布、保存或 AI 任务正在执行的文章需等待任务完成后关闭。

## 保存与恢复

正文写回原 Markdown 文件。发布标题、摘要、关键词、Slug 和分类保存在同目录的 `文章.md.starblog.json` 中，重新打开文章时一起读取。移动文章时，可同时移动这个属性文件。

最近文件和已打开的文件路径保存在配置目录的 `workspace.json`。通过“文件 → 恢复上次打开的文章”恢复标签及上次选中的文件。恢复读取磁盘上的已保存内容，不包含未保存草稿或退出前的撤销历史。

发布与本地保存分开：发布后服务器返回的正文若有变化，会继续显示未保存标记，需要保存后才写回本地文件。公众号排版和草稿发布仍使用原有流程，可以从发布菜单或左侧公众号入口进入。

## 实现与验证

`ArticleWorkspaceViewModel` 管理标签、最近文件、文件去重和关闭流程。每个标签独立持有 `PublishViewModel`，正文、文章属性、AI 操作、发布进度和发布结果不会因切换标签而混用。编辑视图在标签间复用，各文档独立持有编辑器文档与撤销记录，并在布局完成后恢复光标和滚动位置。

运行 `dotnet test StarBlogPublisher.Tests/StarBlogPublisher.Tests.csproj` 验证文档隔离、保存与属性恢复、失败处理、关闭选择、并发打开去重和会话恢复。

界面回归检查：打开两篇文章 → 编辑第一篇并滚动 → 切换到第二篇再返回 → 检查光标、滚动与撤销 → 关闭第一篇并分别检查取消、不保存 → 修改第二篇并保存后关闭 → 从欢迎页重新打开。再检查浅色、深色、最小窗口、分栏及预览模式。
