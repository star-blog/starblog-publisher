# StarBlog Client 功能规划

对照当前 Publisher、线上 `apps/web-legacy`，以及仓库里已在推进的 `/api/v1`。目标是把产品从「发布工具」收成「作者工作台 + 站点运营入口」，而不是再做一套 Admin。

## 产品定位

桌面端继续做「本地写、本地排、再同步到站点」的作者工作台；把每天会碰到的运营接到侧栏。站点配置、SEO、完整表格留给 `apps/admin`。

当前客户端已经很强的部分应保留为差异化能力：多文档工作区、AI 辅助、33 套公众号主题、封面工作室。服务端发布中继只有少量主题，而且是「快照 + 投递草稿」，替代不了本地排版。

当前客户端只接了 3 个 Refit 接口：`IAuth`、`IBlogPost`、`ICategory`。web-legacy 里实际有 16 个 API 控制器；文章列表、删除、推荐、置顶、翻译、评论、摄影、友链、访问统计都已经在线上。

## API 约束

线上仍跑 web-legacy 时，路径是 `/Api/*`，响应包在 `ApiResponse<T>` 里。新栈已经改成 `/api/v1/*`，成功体是裸 JSON，错误是 `ProblemDetails`；登录变成 `POST /api/v1/auth/tokens`。

| | 线上 web-legacy | 新 API |
|---|---|---|
| 登录 | `POST /Api/Auth/Login` | `POST /api/v1/auth/tokens` |
| 文章 | `/Api/BlogPost` | `/api/v1/posts` |
| 响应 | `ApiResponse<T>` | 裸 JSON + `ProblemDetails` |

web-legacy 仍更宽的部分：访问统计（日/时趋势、地理、UA、跳出、转化、慢请求、Top Path）、分类词云、摄影批量导入、译文 CRUD。

新 `/api/v1` 多出来的部分：`GET /users/me`、站点初始化、按 slug 读已发布文章、`POST /posts/imports`、发布渠道与投递。

P0 先对接线上 web-legacy。GUI / CLI / MCP 只打 Application 服务，不直接绑路径，后续再加 V1 适配。

## 分阶段

### P0 · 把「发布工具」收成「内容客户端」

在 Avalonia 里**新增页面**实现，不改现有文章工作区的发布按钮和分类选择器。

- 侧栏增加「站点文章」：分页、搜索、分类、已发布 / 草稿
- 点开后进入新的详情/编辑页，保存走 `Update`；可存草稿、发布、删除
- 可把线上正文下载为本地 Markdown 与 `.starblog.json`（含 `postId`）
- 「分类管理」作为站点文章页的二级页面：改名、删除、显隐、新建
- CLI / MCP：`post list` / `update` / `delete` / `pull`，`category update` / `delete`

现有工作区仍负责本地写作和首次发布。线上稿的改、删、草稿在新页面完成。

### P1 · 高频运营，放在编辑器旁边

- 评论箱：待审、通过、拒绝
- 站点概览：文章 / 草稿数、待审数、最近更新
- 推荐、置顶、从线上 pull 后在浏览器打开

### P2 · 有本地优势再做

- 摄影库：本地选文件、读 EXIF、压缩再传
- 访问简报
- 对接服务端发布中继（不要拆掉本地 33 主题）
- 友链申请、zip 批量导入（更适合 CLI）

## 建议的桌面信息架构

在现有「文章 / 公众号排版 / 设置 / 关于」上只加必要的栏，避免做成后台导航墙。

| 侧栏 | 职责 | 阶段 |
|---|---|---|
| 文章 | 本地 Markdown 工作区 | 已有 |
| 站点文章 | 线上库：列表、草稿、打开、更新、分类管理 | P0 |
| 公众号排版 | 本地主题、封面、草稿箱 | 已有 |
| 动态 | 概览 + 待审评论 | P1 |
| 设置 / 关于 | 博客地址、账号、AI、代理 | 已有 |

## 明确不做

- 不要复刻 `apps/admin` 的 JSON 资源编辑器，也不要把站点 Host、主题、robots、sitemap 搬进桌面
- 不要先做 Tag。模型两端都还没有这个字段
- 不要用客户端替代公众号群发。服务端和本地现在都只创建草稿
- 知乎 / 掘金没有稳定创作者 API；若做，应复制快照并打开官方编辑器

## P0 实现切片

1. Core：文章 list / get / update / delete / pull，分类 update / delete / visibility
2. 新增「站点文章」页面与「分类管理」二级页
3. CLI / MCP 同步上述命令
4. 现有工作区发布流程保持不变
